# Stages 5.3B6–B8 — Unity souvenir integration and acceptance

## Integration

- `Assets/LivingGlass/Integration/LivingGlassFlowIntegration.cs` starts a local visitor identity after Home Begin is accepted and connects New Visitor to closure and the existing Home flow. `Assets/Scripts/AwakeningApplicationController.cs` records confirmed performer selection and the natural Living Portrait release transition, then qualifies the same performer only after the visitor advances Reflection into Closing. The existing configured portrait fallback uses the same release transition. Returning to Gallery, loading a scene, changing language, or rendering Closing does not authorize an assignment.
- The first qualifying journey fixes the visit performer for all six existing IDs. The backend requires a performer when a visit starts, so the client opens the backend visit after the first qualifying route. It submits the four corresponding existing milestones in order and confirms completion before assignment. Additional performer exploration stays on that visit. A local atomic journal holds the random idempotency key, first qualifying performer, and pending reset marker. It stores no session, visit or QR bearer. A later process can recover the existing visit with the same key and request it from Closing. An unresolved server reset blocks opening any replacement server visit, while local exhibition navigation continues.
- `Assets/LivingGlass/Souvenirs/WindowsSouvenirSigner.cs` opens the enrolled current-user key through Windows CNG, checks the Platform Crypto Provider hardware flag and the no-export policy, validates the exact challenge, and signs using the TPM. It neither generates a key nor exports private material. The Player requires the enrolled Windows profile, its existing `%LOCALAPPDATA%/AwakeningCelebrations/SouvenirKiosk/enrollment.json`, and the Windows platform provider. There is no external helper or software-key fallback. [Microsoft NCryptSignHash](https://learn.microsoft.com/en-us/windows/win32/api/ncrypt/nf-ncrypt-ncryptsignhash)
- `Assets/LivingGlass/Souvenirs/SouvenirClient.cs` sends requests to the existing HTTPS Worker origin with redirects disabled. It renews the kiosk session before expiration or on a kiosk-auth rejection. It retries transport and transient server errors on idempotent visit calls once, with a delay. Each request has an eight-second timeout. A lost proof exchange starts again with a fresh challenge. It treats authorization denial, unknown routes, conflict, expiry/revocation, throttling, and paused/unavailable service as bounded UI states.
- `Assets/LivingGlass/Souvenirs/LivingGlassSouvenir.cs`, `Assets/LivingGlass/Presentation/LivingGlassPresentation.cs`, and `Assets/LivingGlass/UI/Styles/LivingGlass.uss` handle the request lifecycle, bilingual Closing and Souvenir sections, scan instructions, fixed countdown, QR rendering and New Visitor. QR textures are scoped to the visitor and destroyed on expiry, reset or controller disposal. The text alternative explains the scan and download actions. There is no external QR generator or third-party runtime network call.
- The only new dependency is the ZXing.Net 0.16.11 netstandard2.0 core DLL and Apache 2.0 license under `Assets/LivingGlass/Souvenirs/ThirdParty/`. The DLL SHA-256 is `f3b823b6fd6492525a7547989056883def5d43be1e12c4f63fa54df73e3c5cfc`. Unity generated the corresponding asset metadata. [ZXing.Net package](https://www.nuget.org/packages/ZXing.Net/0.16.11)
