# UIDocument Architecture Audit

**Audit scope:** `Assets/Scenes/SampleScene.unity`, runtime screen catalog, application/home controllers, imported UXML/USS, and existing Figma fidelity inventory.
**Unity:** 6000.4.7f1.
**Audit baseline:** 2026-11-05.

## Stage 1 — Previous architecture baseline (historical; superseded by Phase 3)

### Scene and ownership

At the pre-refactor baseline, the active scene contained three UIDocuments: `HomeUI_EN`, `HomeUI_ZH`, and one generic page document. This description is retained as history; the Phase 3 implementation record and Phase 4 snapshot below describe the current architecture.

The six performers each have five separately cataloged stage roots (Focus View, Activation, Living Portrait, Release, Post-video AI), each in English and Traditional Chinese. The eight tutorial steps are likewise locale-specific. These are variants of screen families, so each family gets one UIDocument while retaining its existing UXML per locale/performer/state.

At that baseline, assistant theme UXMLs were appended to the generic page document. Phase 3 moved them to a dedicated overlay UIDocument. `AwakeningApplicationController` continues to own overlay bindings and assistant backend session lifecycle. Camera-consent and gesture services remain outside document selection.

### Asset and code inventory

- Runtime catalog: 106 entries, 53 logical screen IDs, 2 locales.
- Catalog-backed UXMLs: 106, with the exact asset association listed below.
- Project UXML files: 106.
- Project USS files: 101 (includes non-catalog/shared stylesheets).
- Existing scene UIDocuments: 3 (two Home + one reused navigation document).
- Existing screen-specific page root controllers: HomeLanguageController for localized Home; other pages are catalog UXML plus central controller bindings.
- Runtime-loaded trees: all 104 non-Home catalog entries; assistant overlay currently uses `VisualTreeAsset.Instantiate()` and appends into the reused page document.
- Panel settings: all current scene UIDocuments reference `Assets/UI Toolkit/PanelSettings.asset` (scale mode Constant Pixel Size, scale 1, reference resolution 1200×800, sorting order asset default 0). The navigation document is raised to 10 in controller Awake; overlay will use 20.
- Gesture/consent ownership: existing interaction scripts and `GestureCameraConsentGate`; no architecture change is planned in that area.

### Dependencies and risks identified

1. The application controller assumes one active `navigationDocument` for root lookup and bindings; route logic is otherwise independent of document ownership. A manager must return the just-activated UIDocument before existing `BindCurrentScreen` is called.
2. `HomeLanguageController` expects both Home documents enabled/active and uses positional mappings; preserve it without hierarchy/content changes.
3. The overlay must receive `HomeInteraction.uss`, preserve input focus/cleanup, and be disabled/cleared on close or page navigation. It must render above any active main document.
4. Consent gate is set false at Awake and recomputed from route + accepted consent. The new manager may not call or change consent services.
5. All document roots use catalog UXML assets; no screen-specific UXML element names or hierarchy need to change.

## Phase 4.2 — Settings Back navigation correction (2026-11-05)
